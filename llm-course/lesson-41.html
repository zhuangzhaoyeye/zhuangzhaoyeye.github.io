第 41 课：在线与无参考优化

上一课我们看到 DPO（直接偏好优化）变体族越改越省，但它们共享一个前提：数据是"别人写好的"，模型从不自己采样。这一课回到"在线"训练——让模型边采样边学，再沿着"删 critic → 删参考模型 → 换优化单元"的路线，把 RLOO / REINFORCE++ / GRPO（组相对策略优化）/ GSPO 串起来，最后回答：在线和离线到底怎么选。

🎯 学完这 6 步你将能够：
① 说清离线 DPO 为什么缺探索、要回在线
② 用 leave-one-out / 组内基线解释"删 critic"的原理，并复算组内优势
③ 分清 REINFORCE++（全局归一化）与 GRPO（组内基线）的口径差异
④ 讲清 GSPO 为什么把重要性比从 token 级换成序列级
⑤ 用三判据（奖励可验证 / 要不要探索 / 显存）选在线还是离线

3纯 REINFORCE 方差大、策略会跑飞，因此补 token 级 KL 惩罚 + 全局优势归一化——这就是 REINFORCE++。

DPO 又稳又省，为什么还要回到"在线"训练这条路？
提示：先想 DPO 训练时模型自己会"开口"生成吗？再想它学的数据是谁写的、覆盖了多少可能。
▾
知识背景
DPO（Rafailov et al., arXiv:2305.18290, 2023）把 RLHF（基于人类反馈的强化学习）换成一次分类，只用固定偏好对，训练时策略从不采样，所以它是离线（offline）的。离线的好处是稳定、便宜，代价是失去探索（exploration）——模型永远看不到自己"没生成过的回答"会得到什么奖励。

上一课我们看 DPO 变体族砍参考模型、加正则，但它们共享一个前提：数据是"别人写好的"，训练时模型自己不生成。因为模型从不采样，所以数据之外的回答它永远看不到、更学不到——这就是"离线"和"在线"的分界线，也是要回到在线的原因。

可以把这类比成两种备考方式：离线是"刷题库"（只练题库里有的题），在线是"边考边改"（每次自己写、当场判对错）——题库覆盖不到的题，刷再多也练不到；而边考边改能遇到新题。在 RL 里，这个"题库覆盖不到"就对应分布外（OOD）区域，模型在那里没有梯度信号。

🧮 离线 vs 在线：训练时到底差在哪

维度离线（DPO 族）在线（RLOO/GRPO 等）

策略是否"开口"否（0 次采样）是（每步采 K/G 个回答）
能不能探索数据之外不能能
Step 2：探索为 0 的代价
情形离线 DPO在线
回答在数据集覆盖内有梯度信号，能学能学
回答在数据集覆盖外无梯度信号，只能靠隐式奖励 r=β·log(π/π_ref) 外推采到就能学
DPO 的隐式奖励 r = β·log(π/π_ref) 只在"数据里出现的那些回答"上有监督；数据之外，模型只能靠外推——这就是 DPO 长度坍缩、β 敏感这些毛病的深层原因。要补探索，就得让模型自己采样、拿采样结果去算奖励，也就是回到在线。

2
回到在线训练，PPO（近端策略优化）最贵的是 critic，能不能干脆不训它？
提示：先想 critic 是干嘛用的——估个"基线"降低梯度方差。同一道题多生成几个答案，能不能让它们互相当基线？
▾
知识背景
RLOO（REINFORCE Leave-One-Out）出自 Ahmadian, Cremer, Gallé 等人的论文《Back to Basics: Revisiting REINFORCE Style Optimization for Learning from Human Feedback in LLMs》（arXiv:2402.14740, 2024）。它回到最基础的 REINFORCE 策略梯度，用 leave-one-out 技巧构造无偏基线，从而删掉 critic（价值模型）。

上一张卡片看到回在线要重新面对 RL 的方差问题——PPO 靠 critic 估基线来降方差。RLOO 问：同一个 prompt 采 K 个回答，每个回答拿"其他 K−1 个的平均奖励"当基线，不就行了吗？

可以把这类比成全班考试：一个学生的"相对水平" = 他的分数 − "其他同学的平均分"，不需要专门雇一个"估分员"（critic）去猜他的分数。这个"去掉自己、用别人平均"的基线就叫 leave-one-out（留一法）。

🧮 RLOO：leave-one-out 基线怎么算（K=4）
Step 1：四个回答的奖励
样本奖励 rleave-one-out 基线（其余 3 个的平均）
11(0+1+0)÷3 ≈ 0.333
20(1+1+0)÷3 ≈ 0.667
31(1+0+0)÷3 ≈ 0.333
40(1+0+1)÷3 ≈ 0.667
Step 2：优势 = 奖励 − 基线
样本优势 A = r − baseline方向
11 − 0.333 ≈ +0.667抬升
20 − 0.667 ≈ −0.667压低
31 − 0.333 ≈ +0.667抬升
40 − 0.667 ≈ −0.667压低
梯度方向就由这些优势决定：奖励高于组平均 → 抬升该回答的生成概率；低于组平均 → 压低。因为基线里不含样本自己，它在期望上无偏——这就是"无参数价值函数"：不用训 critic，每个训练步现算一个基线。
🎯 留下什么问题

有 critic → 多训一个同尺寸模型、还有估计偏差；删 critic 用 leave-one-out → 基线无偏、省一份显存，但方差比学出来的基线略高。下一个问题：删了 critic 的纯 REINFORCE 方差大、不稳定，怎么稳住它？

3
删了 critic 的 REINFORCE 方差大，怎么让它稳定下来？
提示：两件事——优势数值随 batch 乱飘怎么办？策略学得太激进"跑飞"怎么办？各对应什么技巧。
▾
知识背景
REINFORCE++（Jian Hu, arXiv:2501.03262, 2025，最新版标题《Stabilizing Critic-Free Policy Optimization》）补两块让 critic-free 的训练稳定：token 级 KL 惩罚（防策略跑飞）与全局优势归一化（全 batch 减均值除标准差）。

上一张卡片 RLOO 给了无 critic 的梯度，但优势数值会随 batch 漂移、策略会跑飞。REINFORCE++ 用两招稳住：①优势归一化——把整个 batch 的优势减均值、除标准差；②token 级 KL 惩罚——每个 token 的奖励都扣掉它和 SFT（监督微调）模型之间的 KL 散度。

可以把这类比成标准化考试：归一化像"把全班原始分换成标准分（Z 分数）"，让不同难度的卷子也能横向比；KL 惩罚像"扣分项，防止你离课本（SFT 模型）太远、开始胡编"。

🧮 REINFORCE++ 的两招各怎么算
Step 1：token 级 KL 惩罚扣多少
量取值
KL 系数 β0.04
单 token 的 KL 散度0.5（示意）
回答长度50 token
总 KL 惩罚0.04 × 0.5 × 50 = 1.0
原始奖励 − 惩罚后的有效奖励1.0 − 1.0 = 0.0
Step 2：优势归一化（Z 分数）
原始优势均值标准差归一化后
[0.5, 1.5]1.00.5[−1.0, +1.0]
归一化公式 A' = (A − mean) / std：0.5 → (0.5−1.0)/0.5 = −1.0；1.5 → (1.5−1.0)/0.5 = +1.0。归一化让优势的尺度稳定，学习率不再跟着 batch 的绝对奖励值乱调；KL 惩罚让策略每一步都贴着 SFT 模型，不会为刷分而跑飞。
🎯 留下什么问题

不归一化 → 优势尺度随 batch 漂移、学习率敏感；不加 KL → 策略为刷奖励跑飞、复读。下一个问题：REINFORCE++ 用"全 batch"归一化，GRPO 换成"同一题的一组"，这两者差在哪？

4
GRPO 和 REINFORCE++ 都删了 critic，它凭什么还能再删掉参考模型？
提示：先想归一化的口径——用"全 batch"还是"同一题的一组"？再想 KL 惩罚依赖的参考模型，能不能直接去掉。
▾
知识背景
GRPO（Group Relative Policy Optimization）出自 DeepSeekMath（Shao et al., arXiv:2402.03300, 2024）。它用"同一 prompt 一组 G 个输出的平均奖励"当基线，删掉 critic；组大小 G 常见 8~64（DeepSeekMath 用 64，TRL 默认 8）。原论文仍保留对参考模型的 KL 项，但 DeepSeek-R1-Zero（arXiv:2501.12948）用规则奖励把 β 取 0，连参考模型也删了。

上一张卡片 REINFORCE++ 在全 batch 上归一化。GRPO 换个口径：在"同一道题的一组回答"内做相对比较（组内基线），组大小 G 常见 8~64。因为组内是"同题"的对比，基线更贴题；而且 R1-Zero 干脆把 KL 项去掉（β=0），参考模型也省了。

可以把这类比成排名：REINFORCE++ 是"全年级统一排名"（全局归一化），GRPO 是"同一道题的小组内互相对比"（组内基线）——同一道题上谁答得好，直接和同组的人比就够了，不必等全年级算完。

🧮 GRPO：组内基线 + 显存账
Step 1：组内优势怎么算（G=4，奖励 [1,0,0,1]）
样本奖励 rr − 组均值归一化优势
111−0.5=+0.5+1.0
200−0.5=−0.5−1.0
300−0.5=−0.5−1.0
411−0.5=+0.5+1.0
Step 2：删 critic / 删参考模型，省多少显存（以 7B 模型、fp16 为例）
方法驻留模型显存
PPO策略 + critic + 参考 + 奖励 = 4 份4 × 14GB = 56GB
DPO策略 + 参考 = 2 份2 × 14GB = 28GB
GRPO（规则奖励）仅策略 = 1 份1 × 14GB = 14GB
组均值 = (1+0+0+1)÷4 = 0.5；标准差 = 0.5（四个样本距均值都是 0.5），归一化后优势就是 [1, −1, −1, 1]。7B 模型 fp16 约 14GB，PPO 四份模型 56GB、GRPO 一份 14GB，省下 42GB。代价是：组内基线要求同一题采 G 个回答，采样量是 G 倍。
🎯 留下什么问题

组内基线依赖"同一题多采样"，采样量 = G × 题数，比离线贵 G 倍；但换来删 critic + 删参考模型，显存从 4 份砍到 1 份。下一个问题：GRPO 在"每个 token"上算重要性比，可奖励是给整条序列的，这错配了吗？

5
奖励是给"整条回答"的，GRPO 却在"每个 token"上算重要性比，是不是错配了？
提示：先想重要性比 = 新旧策略概率比，它该在一个 token 上算，还是在整条序列的概率上算？
▾
知识背景
GSPO（Group Sequence Policy Optimization）出自 Zheng 等人的论文《Group Sequence Policy Optimization》（arXiv:2507.18071, 2025）。它把重要性比从 token 级改成序列级（长度归一化的几何平均），做序列级 clip，稳定 MoE（混合专家）训练，并用于 Qwen3。

上一张卡片 GRPO 用 token 级重要性比做 clip。GSPO 指出：奖励挂在整条序列上，token 级重要性比是错配——它把优化单元从"单个 token"换成"整条序列"。

可以把这类比成一场球赛：赢了是"整场"的结果，不该按"每个回合"单独算功过、再各自 clip。重要性比 = 新旧策略概率比，GSPO 把它在整条序列上取几何平均，得到序列级重要性比。

🧮 GSPO：序列级重要性比怎么算
Step 1：从 token 级到序列级（几何平均）
tokentoken 级重要性比 π_θ/π_old
11.2
20.9
31.5
Step 2：序列级重要性比 = 几何平均
算式结果
1.2 × 0.9 × 1.5= 1.62
(1.62)^(1/3)（3 个 token 的几何平均）≈ 1.174
序列级重要性比 = (π_θ(y|x) / π_old(y|x))^(1/|y|)，其中 |y| 是序列长度；它可以等价写成 PPL_old / PPL_θ（新旧困惑度之比）。取几何平均（即长度归一化）让长短不同的回答落在同一个数值尺度上，clip 范围不再随序列长度漂移。
🎯 留下什么问题

token 级 → 长序列的 clip 范围漂移、有长度偏差；序列级 → 长度归一化、数值范围统一、稳定 MoE。最后一个问题：在线（RLOO/REINFORCE++/GRPO/GSPO）和离线（DPO 族）到底怎么选？

知识背景
在线（RLOO / REINFORCE++ / GRPO / GSPO）与离线（DPO 族）不是新旧关系，而是"要不要探索、奖励能不能即时算、显存够不够"这三笔账的取舍。本课收口成一张选型表，第 43 课还会把它展开成最终的选型判据。

前面五张卡片走完了在线这条路：RLOO（删 critic）→ REINFORCE++（归一化 + KL）→ GRPO（组内基线、删参考模型）→ GSPO（序列级）。现在收口：在线和离线不是谁取代谁，是三笔账的取舍。

可以把这类比成备考策略：题目固定就"背答案"（离线），题目会变、要现场应变就"边做题边改"（在线）——但边做题边改要花更多时间（采样成本），背答案则不用。

🧮 三个判据 + 六种方法横评
Step 1：三个判据
判据回答"是" →回答"否" →
奖励能当场验证？在线 RL（规则/程序奖励）偏好对齐（DPO 或需奖励模型）
要探索新回答？在线（GRPO/RLOO 等）离线（DPO 族）
显存够驻留多模型？可上 PPOGRPO / RLOO 等省显存的
Step 2：六种方法横评
方法驻留模型数采样探索
DPO（离线）2（策略+参考）0无
PPO4每步采样有
RLOO3（策略+参考+奖励模型）每步采 K有
REINFORCE++3（策略+SFT参考+奖励模型）每步采样有
GRPO（规则奖励）1（策略）每步采 G有
GSPO1（策略）每步采 G有
一句话收口：奖励能验证 + 要探索 + 显存紧 → GRPO/GSPO；数据已备好、不折腾 → DPO；有算力想稳 → PPO。细节选型见第 43 课。
🎯 关键认知

整课压成三句话：离线缺探索、在线补探索但要付采样与显存两笔账；删 critic（leave-one-out / 组内基线）、删参考模型（β=0）都是"砍掉不必要的模型"；GSPO 把优化单元从 token 换成序列，纠正了"奖励给序列、却在 token 上算比"的错配。下一课进入第二条线：偏好训不了"算对"，推理强化要用 0/1 对错信号。
