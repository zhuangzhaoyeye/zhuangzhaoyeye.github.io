第 35 课：决策模型

前面从 Transformer 讲到 Agent，模型始终在"写句子"——每答一道选择题，它都要逐字生成一段文字再猜答案。这一课问一个更底层的问题：如果任务本来就是"选一个 / 打个分 / 判个对错"，为什么非要用"写一段话"来完成？我们沿着"生成的不匹配 → 成本 → 可靠性 → 概率的本质"一路推，最后逼出一个新范式——决策模型（decision model）：它不写句子，直接输出每个选项的概率。

🎯 学完这 6 步你将能够：
① 说清"生成"与"决策"这两种任务对模型输出的要求有什么根本不同，并判断一个任务该走哪条路
② 用具体数字算清自回归做决策的代价（token 数、前向次数、时间），并对比决策模型的单次前向
③ 解释为什么自回归会编造选项、格式漂移、信心不可靠、换序就变，而决策模型为什么能同时避开这四点
④ 分清「决策模型」（Drex / DPDM）与「推理模型」（第 12 课）这两条分岔路各自解决什么
🗺 本节推理链（6 步逻辑递进：从"任务本质"到"决策模型"）
1一个"决策"任务（选答案 / 打勾 / 打分）的本质，是输出每个选项的得分，而不是写一段关于答案的文字——这就要求先看清：自回归 LLM 逐 token 做选择时，实际在"写一句话"，而不是"选一个答案"。决策要的是分数，不是文字。
↓
2既然「决策要的是分数，不是文字」，那么用"写句子"去选一个答案就要付出多余代价——这就要求算清这笔账：生成 N 个 token 就是 N 次前向，而决策模型一次前向就够了。生成比选择贵一个量级。
↓
3既然「生成比选择贵一个量级」，而且"写"还会跑偏——这就要求正视自回归的格式漂移：它逐 token 生成时可能编造不存在的选项、输出格式五花八门、还得事后解析。写出来的话会跑偏。
↓
4既然「写出来的话会跑偏」，那么即便写对了，隐式的"信心"也不可信、换个选项顺序答案还会变——这就要求区分"生成出来的话"和"真实的 token 级概率判断"。话对≠信心对。
↓
5既然「话对≠信心对」，所以回到任务本质：决策要的本就是概率分布（而非生成 token）——这就要求把"决策"从"生成"里拆出来，让模型直接输出每个选项的概率。决策的本质是概率。
↓
6既然「决策的本质是概率」，所以需要一个专门学"条件预测"的模型（不生成 token、直接输出概率）——这就要求看 JEV（闭源先驱）、Drex（开源决策模型）、DPDM（共享冻结预测器）怎么做到、效果如何，并分清它和"推理模型"的分岔。决策要专门的模型。

1
让 LLM 从 A/B/C/D 里选一个答案时，它到底是在"选"还是在"写"？
提示：想想模型是怎么产出答案的——它是一下子蹦出"B"，还是一个字一个字地把答案"写"出来？
▾
知识背景
自回归语言模型（autoregressive，即"每次只生成下一个字、再把新字拼回输入接着生成"）是 GPT 一族的根基（Radford 等，2018，Improving Language Understanding by Generative Pre-Training）。它的训练目标是"预测下一个词"，所以推理时也只会"续写"——哪怕任务只是"四选一"，它也只会一个字一个字地往外写一段话，再在话里"说出"答案。

这是整课的第一问：一道选择题，模型到底在"选"还是"写"？

因为模型只有一个动作——自回归（autoregressive）生成：每一步预测下一个 token，再把预测结果拼回输入。它没有"从四个里挑一个"的捷径，只能把"选 B"这件事写成一段文字。就像让你从四张答题卡里选一张，你却必须先写一篇短文、再在文末说"我选 B"——不是不能，是绕了一大圈。所以先看清这一圈绕在哪。

🧮 第一笔账：一个"选 B"被写成了多少步
Step 1：逐 token 生成"答案是 B"
步骤这一步生成此时输入里已有哪些词
1"答案"（题目）
2"是"题目 + "答案"
3"B"题目 + "答案是"
算术无关的一条观察：光说出"答案是 B"就要 3 次生成（每次都是一次完整前向）。而任务真正需要的只是那一个"B"。
Step 2：真实回答比这更长
生成内容token 数（示意）
最短："B"1
常见："答案是 B"3
带解释："答案是 B，因为……"20–50
算术：3 token = 3 次前向，50 token = 50 次前向——决策任务要的"一个选择"，被自回归放大成了 1 到 50 个 token 的文本，每一个 token 都是一次前向计算。
🎯 核心矛盾

任务要的是一个选择（挑出 B），模型却只能生成（写一段话）。没有"直接选"这条路，所以它只能把选择"翻译"成文字，再让下游从文字里把答案"挖"出来。

2
选一个答案，为什么要付出一整段话的计算代价？
提示：把"写一个字"看成"算一次"。写 30 个字的答案，和只输出一个概率，各自要"算"多少次？
▾
知识背景
自回归生成的成本与输出长度成正比：每多生成一个 token，就多一次完整的前向计算。而决策模型（decision model）的诉求恰恰相反——Drex 家族（Nace AI，2026）报告其最大模型 Drex Max 单次决策约 183 毫秒，因为它是"一次前向直接输出每个选项的概率"，没有逐 token 生成的循环。

上一张卡片看到：选择被翻译成了文字。这一张问：这笔翻译费是多少？

因为自回归的每一步生成都是一次完整前向（forward，即把输入从头到尾过一遍网络），生成 30 个 token 就是 30 次前向；而决策模型一次前向就同时给出所有选项的概率。就像点外卖：自回归是"一道菜一道菜地单独下单、每次付一次配送费"；决策模型是"一次下单把整桌菜都点了"。所以把两种路径的计算量摆在一起算。

🧮 第二笔账：前向次数差一个量级
Step 1：两种路径的前向次数
路径要算几次前向说明
自回归生成 30 token30 次每 token 一次
决策模型（单次前向）1 次同时出全部概率
倍数30 ÷ 1 = 30×——
算术：30 次对 1 次，计算量差 30 倍（此处 30 是"带解释的回答"的 token 数示意；最短的"B"是 1 token，倍数为 1×，代价取决于你让它写多长）。
Step 2：换成时间（示意口径）
路径耗时（示意）
自回归生成 30 token（约 50 token/秒）30 ÷ 50 = 600 ms
Drex Max 单次决策约 183 ms
相对600 ÷ 183 ≈ 3.3×
算术：在"自回归 50 token/秒"这个示意速率下，30 token 约 600ms，是 Drex 报告 183ms 的约 3.3 倍。50 token/秒是示意假设，真实速率随模型与硬件变化；Drex 的 183ms 来自其论文/官方口径。
🎯 核心矛盾

同样的"选一个答案"，写出来要 30 次前向、几百毫秒；直接输出概率只要 1 次前向、183 毫秒。代价不是固定的，而是随"你让它写多长"线性上涨——写越多、浪费越多。

就算不计成本，让 LLM 从 A/B/C/D 里选，它为什么还可能选出一个根本不存在的"E"？
提示：想想"生成"的本质——它是不是照着概率"抽"下一个字？抽的时候，有没有一种可能抽出一个题目里没有的选项？
▾
知识背景
自回归生成是"逐步采样"：每一步都从词表上的概率分布里抽一个 token。因为没有"只能输出 A/B/C/D 之一"的硬约束，生成过程随时可能抽出一个题目之外的词——表现为编造选项、格式漂移（format drift）、或输出无法被程序解析的文本。这正是下游要写大量"解析 + 重试 + 兜底"代码的原因。

上一张卡片算了成本的账。这一张问：除了贵，写出来的答案还可靠吗？

因为自回归的每一步是从词表里"抽"下一个字，而词表里有几万个 token，不是只有 A/B/C/D 四个。没有硬约束时，它完全可能抽出"E"、或者输出"我认为是 B"这种需要额外解析的文本。就像让一个会写字的人"圈答案"，他却可能画出一个题目里没有的符号，或者写一句"我猜是B"——你得再费一道工序去读懂他到底选了什么。所以看它到底能"跑偏"到哪。

Step 1：同一个"选 B"，自回归可能写成几种样子
可能的输出下游要做什么
"B"直接用
"答案是 B"要解析出"B"
"我认为选 B"要解析出"B"
"E"（编造）无法处理，重试
算术无关的一条观察：同一个答案可以有无穷多种"写法"，每一种都要下游去解析；最坏情况是编造出选项之外的东西。
Step 2：格式漂移的代价
做法是否需要解析失败后果
自回归输出文本是（格式不定）解析失败 → 重试 / 报错
决策模型输出概率否（结构固定）直接取 argmax 或按概率用
算术无关的一条对比：决策模型输出的是固定结构（每个选项一个概率），没有"解析"这道工序，也就没有"解析失败"这层风险。
🎯 核心矛盾

自回归的"自由"在生成任务里是优点，在决策任务里是负担：它没有"只能选 A/B/C/D"的边界，所以可能编造、可能漂移、必须解析。决策模型把输出空间从"整张词表"收窄到"这几个选项"，跑偏这件事从根上就不存在。

4
模型说"我很确定选 B"——它真的确定吗？换个选项顺序它还会选同一个吗？
提示：把"它说确定"和"它真实可信"分开想。再想：同样的题，把 A 和 C 换个位置，答案会不会变？
▾
知识背景
自回归模型说出口的"我确定"只是一段文字，不等于真实的概率判断——它的"信心"是隐式的，藏在它生成的那句话里，无法直接读出、也常与事实不符（即校准性 calibration 差）。同时，自回归对选项的顺序敏感：同样的题，A/B/C/D 换个位置，答案可能就变。Drex 论文特别强调其模型"calibrated"（校准的）且"stable under reordering of the options"（对选项重排稳定）。

上一张卡片看到逐 token 生成会跑偏。这一张问更隐蔽的一点：就算格式写对了，它的信心可信吗？

因为自回归只输出一段话，"信心"没有独立的数值出口——你说"确定"，可你没有给出"90% 还是 55% 的把握"这个数；而且它对选项的排列位置敏感，换个顺序就可能改口。就像问一个人"你确定吗"，他拍胸脯说确定，但你把两个选项左右对调再问，他却犹豫了——这种"确定"不可靠。所以要一个能直接读出把握大小的输出。

🧮 第四笔账：话对 ≠ 信心对
Step 1：隐式信心 vs 显式概率
输出形式能读出"把握多大"吗例子
自回归："我确定选 B"不能（只有文字，无数值）是 90% 还是 55%？不知道
决策模型能（每个选项一个数）P(B)=0.72
算术无关的一条对比：决策模型的概率是显式的数字，可以直接用来定阈值、算期望、做风险控制；自回归的"确定"只是形容词。
Step 2：换序稳定性
情形自回归（对顺序敏感）决策模型（对重排稳定）
选项顺序 A/B/C/D选 BP(B)=0.72
换序 D/C/B/A可能改选 CP(B) 仍 ≈ 0.72
算术无关的一条对照：换序是"同一个决策"的无关扰动，理想模型不应受影响；自回归会受影响（答案漂移），决策模型则声称对此稳定（Drex 口径）。
🎯 核心矛盾

决策需要两样东西：一个可读出的把握（概率）和不受无关扰动影响（换序不变）。自回归把把握藏在文字里、又对顺序敏感；决策模型把概率显式输出、并对重排稳定——这才是"可依赖的决策"。

知识背景
这就是"决策模型"的定义：给定一个 state（状态，即一份文档、记录或 agent 上下文，可选带图像）和若干 question（每个问题是在一组选项里做选择 / 判断是或否 / 在有序尺度上打分），模型一次性输出每个选项的概率，而不是生成文字。Drex（Nace AI，2026）是一个家族、共 4 个开源决策模型，输出即概率分布。

前面四张卡片把"逐 token 生成做决策"的四个问题摆完了。这一张是转折：回到任务本身——决策要的到底是什么？

因为四选一、打勾、打分，这些任务的答案天然是"每个选项一个分数/概率"，而概率有个硬约束：加起来等于 1。既然要的就是概率，那就让模型直接输出概率，而不是输出一段"藏着概率"的文字。就像裁判打分：他举起"9.5 分"的牌子，而不是写一段"我觉得这个表现值 9.5 分"的评语。所以看决策模型怎么定义输入输出。

🎯 核心矛盾

决策要的从来不是"一段话"，而是"一个概率分布"。自回归把概率塞进文字里让你猜；决策模型把概率直接摆出来——于是成本、跑偏、信心、换序这四个问题，都在"输出概率"这一设计里被同时化解。

6
怎么训练一个"只会做决策"的模型，并且让它举一反三到没见过的新问题？
提示：一个模型要同时会"判断工具用没用对、候选好不好、推理对不对"——这些不同任务，能不能共用一个"预测器"？
▾
知识背景
"决策模型"这个赛道最早是被 JEV（TypeSafe，2026）点爆的——一个闭源托管的模型，只能调 API、不公开权重，但它第一次证明了"不写文字、直接输出每个选项概率"这条路线走得通，取名自经济学家杰文斯（Jevons）的悖论。随后开源阵营追了上来，给出两条开源实现路径。Drex（Nace AI，arXiv:2611.07854）是"决策基础模型"：家族 4 个开源模型，旗舰 Drex Max 在真实数据决策上可与前沿模型竞争，同时快、校准好、对选项重排稳定；论文与模型页称 Drex 2.0 为 35B 参数、约 3B 每 token 激活（MoE，即"混合专家"——每次只激活一部分专家，参数量大但算得少）。DPDM（Decoupled Predictive Decision Making，Stable AI 与清华，arXiv:2611.02075）则把决策拆成两半：语言模型做语义表示，一个冻结的共享条件预测器做预测，全程不改任何权重。

上一张卡片确立了"输出概率"的方向。这一张问：这个"决策模型"到底怎么造？

因为agent 里有多种决策（工具判不判、候选好不好、推理对不对），如果每个都单独训一个模型，成本爆炸；所以要一个能"举一反三"的通用预测器。就像一个裁判可以同时给体操、跳水、花样滑冰打分——不是每项运动都配一个裁判，而是"打分"这个通用能力复用。所以看三条路：闭源先驱 JEV、开源追平的 Drex、解耦架构的 DPDM。

项数值

Step 3：DPDM 的架构与效果
组件职责
语言模型（语义编码器）把记录转成语义表示
共享条件预测器（冻结）从表示预测各决策目标
关键点推理时不改任何权重
指标数值
50 个基准的平均准确率（few-shot 基线）78.80%
加 DPDM 后84.92%
提升84.92 − 78.80 = +6.12 个百分点
算术：84.92% − 78.80% = +6.12pp。关键在"冻结"——预测器不训练，靠预训练得到的通用推理能力，配上具体任务的 evidence（证据）就完成预测。
Step 4：和"推理模型"（第 12 课）分岔
路径做法方向
推理模型（第 12 课）更长链式思维（CoT）更长的生成
决策模型（本课）砍掉生成、直接出概率更短的输出
算术无关的一条分岔：面对"难决策"，第 12 课往"多想几步"走，本课往"不写直接判"走——一个加生成、一个减生成，解决的是两类不同任务。
🎯 关键认知

决策模型不是"把 LLM 变小"，而是换一种输出契约：输入 state + question + options，输出概率分布。闭源先驱 JEV 点爆了这条路，Drex 用 MoE 把 35B 压到每 token 只激活 3B、单次 183ms，并在 Decision Index 上反超 JEV 10.1 分；DPDM 用一个冻结的共享预测器，50 个基准平均 +6.12pp 且不改权重。它和"推理模型"是两条相反的路：一个靠更长思考，一个靠更短输出。
