第 16 课：量化与压缩

上一课我们把推理的瓶颈定位到了显存与带宽。这一课回答一个更直接的问题：能不能让每个参数少占几个字节？量化的动作只有一个——用一把粗糙的尺子替掉高精度数字；但它牵出三个必须分开对待的对象——权重、激活、以及 KV Cache（把每个 token 算过的 Key/Value 存下来、后面直接复用不重算）；还有一条被反复误用的质量指标（困惑度），以及一个绕不开的边界：什么时候压精度就够了、什么时候必须换一个更小的模型。本课只讲推理侧量化，训练侧的 FP8 已在第 14 课讲过。

🎯 学完这 6 步你将能够：
① 写出量化的 scale / zero-point 公式，并算出对称、非对称、分组三种选择的误差差多少
② 用一个离群值算例解释"为什么 int8 几乎无损、int4 开始塌"
③ 说清权重 / 激活 / KV Cache 三种量化对象的差异，并算出 4-bit 能换回多少显存与吞吐、以及怎么评测才不骗自己
🗺 本节推理链（6 步逻辑递进：从"有损替换"到"量化的边界"）
1模型要上线服务，必须同时把显存占用压下去、把每个 token 的搬运量压下去——这就要求先看懂量化对这堆数字做了什么：它用一把只有 16 个刻度的尺子替掉高精度浮点，每个数只能落在最近的刻度上。量化的本质是有损的刻度替换。
↓
2既然「量化的本质是有损的刻度替换」，所以要问：为什么 8 位几乎不掉分、4 位却断崖？——因为隐藏状态里藏着极少数幅度极大的离群值，它们把刻度范围整条撑开，让绝大多数正常值挤在零附近；8 位还剩几十个刻度能容纳，4 位只剩 16 格就被撑爆，perplexity 这时反而看不出变化。离群值决定低位宽的成败。
↓
3既然「离群值决定低位宽的成败」，所以不能把所有权重与激活一视同仁——因此要把量化对象拆成三种分别对待：静态的权重（可离线慢慢校准）、动态的激活（每次输入都变、离群最凶）、以及运行时才长出来的 KV cache。三种对象的难度不同。
↓
4既然「三种对象的难度不同」，所以工业界默认只动最容易的那一类（W4A16）——因为权重静态、离群可离线处理，压到 4 位就能把 140 GB 变成 35 GB，decode 每个 token 的搬运量也一起降到四分之一。先压权重换取显存与带宽。
↓
5既然「先压权重换取显存与带宽」，这就要求能证明"确实没掉分"——于是必须先看清困惑度（perplexity）这个指标有多迟钝：它只涨 0.03 时，任务分可能已经掉了好几个点。困惑度不足以证明无损。
↓
6既然「困惑度不足以证明无损」，这就要求给量化划出一条可判定的边界——它能压权重、激活与 KV cache，但只改每个参数的字节数、改不动参数量级，所以一旦显存目标跨过量化能到的下界，就必须靠蒸馏换一个更小的模型，最后在"压精度"与"换小模型"之间做选择。量化有边界。

把 fp16 权重压成 int4，一个浮点数凭什么能塞进 16 个刻度里？
提示：先想清「尺子」上有几格、格距由谁定；再想非对称和分组为什么能把误差压得更小。
▾
知识背景
量化的标准写法是 q = round(x / s) + z，还原时 x̂ = (q − z) × s：s 是缩放因子（scale），决定相邻刻度隔多远；z 是零点（zero-point），决定刻度从哪开始。z = 0 时叫对称量化，z ≠ 0 叫非对称量化。GPTQ（Frantar 等，arXiv:2210.17323，2023）与 AWQ（Lin 等，arXiv:2306.00978，MLSys 2024 最佳论文）都采用分组（group-wise）方案：把权重切成若干组，每组共享一套 s 与 z——GPTQ / AutoAWQ 的实现默认 group_size = 128，而更小的 64 也常见（QIGen，arXiv:2307.03738，示例即为每 64 个权重共享一套 scale 与 zero-point）。本课只讲推理侧量化；训练侧的 FP8 已在第 14 课讲过。

前几课我们把模型"服务出去"了：先看清推理被 KV 卡住（第 15 课）。这一课回到模型本身——能不能让每个参数少占几个字节。

量化的全部动作只有一句话：给一串浮点数定一把尺子，再把每个数挪到最近的刻度上——因为模型里每个 token 都要乘过这些权重矩阵，权重少占一个字节，显存与搬运量就少一分。位数决定尺子上有几格——4 bit 就是 16 格。这就像把一张高精度照片另存为低质量版本：格子越少，颜色越容易被"就近归并"，丢掉的是细节（数字精度），保住的是轮廓（模型的行为）。

真正决定成败的不是"用了几个 bit"，而是格距 s 怎么定：s 定小了，超出范围的值会被截断；定大了，绝大多数值又都挤在零附近。下面用一组具体权重，把这把尺子画出来。

Step 2：同一组权重，对称与非对称的格距差多少
方案扫过的范围格距 s一个数的最大误差 s/2
对称（z = 0，用 −7 ~ 7）[−1.6, 1.6]1.6 / 7 = 0.2290.114

算术：一组权重 [0.8, −0.4, 1.2, −1.6]。对称方案最大绝对值 1.6，格距 1.6 ÷ 7 = 0.229；非对称方案只扫真实范围 1.2 − (−1.6) = 2.8，格距 2.8 ÷ 15 = 0.187，误差上限从 0.114 降到 0.093，小了约 18%（0.229 ÷ 0.187 = 1.22）。这一步的直觉是：对称为了保住"0 必须落在刻度上"多扫了一段对称空间，非对称则把每一格都花在真实数据上。

8 个权重（示意）整层共用一个 s0.05 会被还原成每 4 个分一组0.05 会被还原成

算术：整层最大绝对值 3.2，格距 3.2 ÷ 7 = 0.457，于是 0.05 除以 0.457 只有 0.109，四舍五入到 0——直接被抹掉。切成每 4 个一组后，前半组的最大值只有 0.12，格距降到 0.0171，0.05 落在第 3 格上，还原成 0.051。这就是所有主流方法都把 group size = 128 当默认值的原因：分组把"一层的动态范围"拆成"每组各自的范围"。
🎯 关键认知

量化有三个旋钮：位宽（决定刻度总数）、对称性（决定刻度怎么摆）、分组粒度（决定每套 s/z 管多少个数）。位宽决定上限，后两者决定实际能不能逼近这个上限。所以"4 bit"从来不是简单地把 16 个格子铺开——它是"非对称 + 分组"之后每个数尽可能贴近刻度的结果。代价是每组要多存一套 s 与 z：group = 128 时约 0.031 B/参数（折合 0.25 bit/参数），这是下张卡片里"4× 压缩为什么实际只有 3.8×"的来源。

为什么 8 位几乎不掉分、4 位却开始塌？
提示：找一个"正常值都在 0.1~2 之间、却混进一个 50"的通道，看看这个 50 会把格距推到多大。
▾
知识背景
这个问题由 LLM.int8() 给出关键观察（Dettmers 等，arXiv:2208.07339，NeurIPS 2022）：当模型超过约 6.7B 参数后，隐藏状态里会出现系统性的极大幅值特征——它们高度稀疏却极其稳定，在 6.7B 规模上每序列约 150,000 个离群值，却只集中在整个 Transformer 的 6 个特征维度上。论文的做法是把这些离群维度单独用 fp16 计算，其余 99.9% 的值仍走 int8，于是 175B 模型可无损降到 8 bit。另一条路线是 SmoothQuant（Xiao 等，arXiv:2211.10438，ICML 2023）：承认"权重好量化、激活难量化"，用一个数学等价变换把量化难度从激活搬到权重上，从而实现 W8A8。

上一张卡片说了量化是一把有损的尺子；这一张回答最常被问的那个问题——为什么位宽一降到 4 位就崩，8 位却几乎没事？

答案不在"4 比 8 少 4 个 bit"这个数量上，而在离群值上——因为尺子的格距是按最大值定的，最大值一离群，格距就被整条撑开。可以随便挑一个隐藏层通道，它的值大多安静地待在 0.1 ~ 2 之间，偶尔却蹦出一个 50。格距被这个 50 撑开后，绝大多数正常值的间距就被压缩到不足一格。8 位还有几十个格子可分，4 位只有 16 格——一格都不剩。而这个过程中，困惑度（perplexity）往往还看不出异常。

这可以类比成"用一把以公里为刻度的尺子去量一根头发"：不是尺子不准，是它把全部分辨率都花在了那个最长的东西上。下面用具体数字把这条曲线算出来。

🎯 关键认知

"int8 近无损、int4 开始掉"不是玄学，而是离群值撑开格距的必然结果：格距由最大值定，离群值把格距放大到约 18 倍（本卡离群值是正常最大值的 25 倍），正常值就被挤到不足一格。8 bit 靠格子多，勉强还能分出 4 档；4 bit 直接归零。所以真正的分界线不是"几个 bit"，而是这一层有没有离群值、它比正常值大多少倍。反向证据同样重要：后续研究（arXiv:2405.20835）发现新模型（Llama-2/3、Mistral）的离群值已明显变温和，Mistral 7B 近乎免疫——别把 OPT 时代的老结论当定律。

权重、激活、KV Cache，为什么只有激活最难量化？
提示：分别问一句"这个数什么时候才知道有多大、能不能离线反复试错"，答案就出来了。
▾
知识背景
工业界用缩写标明量化对象：W4A16 = 权重 4 bit、激活 16 bit；W8A8 = 权重与激活都 8 bit；KV 量化则单独命名。SmoothQuant（arXiv:2211.10438，ICML 2023）点破了"激活难量化"的根因：激活里的离群值是输入相关的动态值，离线只能用校准集近似估计范围。KV Cache 的量化由 KIVI（Liu 等，arXiv:2402.02750，ICML 2024）给出关键结论：K 应逐通道（per-channel）量化。V 则相反，应逐 token（per-token）量化——因为 K 有跨 token 稳定的离群通道，V 没有。KIVI 做到 2-bit 时几乎不掉质量，峰值显存降 2.6×、批大小可到 4×、吞吐提升 2.35× ~ 3.47×。

上一张卡片说明离群值出在激活里；这一张把量化对象拆开——同样是"一组浮点数"，权重、激活、KV Cache 的难度为什么天差地别？

分界线只有一个问题：这个数是什么时候才知道它有多大的——因为"能离线反复优化"的前提，正是提前知道数值。权重在训练完就固定了，我们可以离线拿校准数据反复试、慢慢优化；激活是每次前向才算出来的，同一个通道这次是 0.1、下次可能是 50，离线只能估个近似范围；KV Cache 更晚——它是运行时逐 token 长出来的，连"一共有多少个数"都要等序列走完才知道。这就像做菜：冷冻食材（权重）可以提前腌好慢慢炖，现杀的鱼（激活）得当场处理，而 KV Cache 相当于边吃边上的菜——你没法提前准备。

正因为难度不同，三种对象的量化方案、粒度、代价也不同，下面逐项对齐。

🧮 第三笔账：三种量化对象的对照表

🎯 关键认知

三种对象的困难排序由"数值何时确定"决定：权重（静态，最容易）< KV Cache（运行时，但有统计规律）< 激活（动态，离群最凶）。所以工业默认是 W4A16——只动最容易、收益又最大的权重，绕开最难的激活；想要算力加速才去做 W8A8（要付校准与 SmoothQuant 的功课）；KV 量化则通常用 fp8 打底、KIVI 类方案做更低比特。这条排序也是下一张卡片"4 bit 换来多少"的前提。

显存这笔账非常直白：权重显存 = 参数量 × 每个参数的字节数。bf16 是 2 字节，4 bit 是 0.5 字节，理论就是 4×。吞吐这笔账要用到第 15 课的结论：decode 是带宽受限的，每一步的耗时约等于"把权重读一遍 ÷ 显存带宽"——读得少，就快，就像搬砖时每次少搬几块，来回的趟数自然就少了。

但两笔账都要扣掉一个开销：分组量化每组要额外存一套 scale 与 zero-point（各 2 字节）。group = 128 意味着每 128 个权重多花 4 字节，折合约 0.031 B/参数（≈ 0.25 bit/参数）——这是"4× 压缩实际只有 3.8×"的来源。

W4A16 的收益是不对称的：显存稳稳拿到约 3.8×，吞吐只在 decode 上兑现、且要打折到 2 ~ 3×。原因上一课已经给出——decode 带宽受限、prefill 算力受限。所以"该不该量化"要按业务问：如果是长输出、高并发（decode 主导），4-bit 收益最大；如果是长 prompt、短输出（prefill 主导），W4A16 主要帮你省显存，加速有限。

▾
知识背景
困惑度（perplexity）是语言模型的经典指标，本质是"平均每个 token 的预测不确定度"，它天然是一个被平均掉的数。GPTQ 论文报告 4-bit 的 OPT-175B 困惑度只涨 0.03，看起来无损；但 Qwen3 量化的系统评测（arXiv:2505.02214，2025）显示，4-bit 下 Qwen-8B 的 MMLU 从 74.7 掉到 69.3（−5.4 分）。另一项覆盖 7B ~ 405B 的评测（arXiv:2409.11055）进一步指出：量化后的模型在指令跟随与幻觉检测上的退化最明显，且 MT-Bench 这类评测对高能力模型的区分力有限。结论是：用一个平均值去验收量化，等于用平均体温判断一个发烧的人。

上一张卡片把 4 bit 的收益算清了；但"省了显存"只是半个答案——另一半是它掉了多少分，而这个"多少"极大程度上取决于你用什么尺子量。

困惑度低，只说明模型对"常见文本的下一个词"依然猜得准；它衡量不了模型会不会听懂指令、会不会编造事实、能不能在长上下文里找到关键信息。这些能力恰恰是量化最容易伤到的地方，因为它们依赖少数"关键权重/激活"，而困惑度把损失平摊到了全部 token 上，把塌方稀释成了看不出的波纹。这就像一个学生的平均分：总分看着没变，但偏科可能已经很严重了。

所以真正的问题不是"困惑度涨了多少"，而是"我的业务能力掉没掉"——下面用一个反差极大的例子说明。

🎯 关键认知

验收量化有一条铁律：困惑度是"及格线"而不是"验收线"。它涨一点点只能说明"没有灾难性崩坏"，证明不了任务能力没退化。正确的做法是——先看困惑度排除崩坏，再用与业务对齐的任务基准（指令跟随 / 幻觉 / 长上下文）和量化前基线做对照。反向证据也要记住：新模型对量化越来越稳健（arXiv:2405.20835），老论文的"掉分幅度"不能直接套到今天的模型上。

都想要更小更快，什么时候压精度就够了、什么时候得换个模型？
提示：量化改的是"每个参数几个字节"，蒸馏改的是"一共有几个参数"——先判断你的瓶颈卡在哪一边。
▾
知识背景
把模型做小有两条正交的路：量化（压每个参数的字节数，部署时做，通常只要几小时）与蒸馏（训练一个更小的学生模型去模仿教师，训练时做，要一次完整训练）。蒸馏的概念由 Hinton 等提出（arXiv:1503.02531，2015）；在 LLM 上的著名实践是 DeepSeek-R1 蒸馏出 1.5B ~ 70B 的一系列小模型。两项技术可以叠加：先蒸馏出更小的模型，再对它做量化。2026 年的统一评测 UniComp（arXiv:2602.09130）给出的结论是：量化在"效率 vs 成本"上的综合权衡最好——蒸馏能达到更高效率，但代价是一次完整训练。

上一张卡片讲了怎么验收量化；这一张回答最后一个决策问题——当你需要"更小更快"时，应该压精度，还是换一个更小的模型？

关键是把两条路改的东西分开：量化改的是"每个参数几个字节"，蒸馏改的是"一共有几个参数"。这就像搬家：量化是把每件行李压缩打包（件数不变、每件更小），蒸馏是干脆换一批更少的行李（件数变少）。两者作用在不同维度上，所以原则上可以叠加。

判断顺序也很明确：先问"模型放得下吗、服务得起吗"——放得下就用量化，收益快、成本低；只有当量化到底也放不下、或延迟预算仍然超标时，才需要动用蒸馏。另外要分清作用对象：量化不只作用于权重，也能压激活与 KV cache——所以"要不要量化"和"要不要蒸馏"是两个独立的问题。下面把三条路线的账一起算。

🧮 第六笔账：三条路线的压缩账
Step 1：量化与蒸馏改的是不同的量

🎯 关键认知

决策顺序只有三步：① 先试量化（几小时、约 4×、掉 1 ~ 3 分）——它解决绝大多数"服务太贵"的问题；② 量化到底仍放不下、或延迟仍超标，再考虑蒸馏（一次训练、改参数量的量级）；③ 两端都要，就先蒸馏再量化，两个乘数相乘。而这一切的前提是上一张卡片那句——量化之后必须用任务基准验收，不能只看困惑度。到这里，推理侧的显存与压缩讲完了；下一课我们把镜头拉远，看这些组件怎么被一个推理引擎组装起来。
