第 5 课：逐层解剖一个模型

前面三节课我们学了 Transformer 的原理、五大改造、Tokenization。现在把所有这些拼起来——以 Llama 2 7B 为标本，从 Embedding 到 LM Head，一层一层拆开看 tensor 形状和计算量。

🎯 学完这 6 步你将能够：
① 画出 Llama 7B 的完整架构图，标注每一层的 tensor 输入输出形状
② 手工推算 Attention 层和 FFN 层的参数量和 FLOPs
③ 从"你好"两个 token 开始，追踪它们经过 32 层后的完整变化过程
🗺 本节推理链（6 步逐层递进：从"算清每个 tensor"到"拼出一次前向的 FLOPs"）
1要做显存估算和 FLOPs 核算，必须先把 整体结构 拆开算清参数量（Embedding → 32×Block → LM Head）—— 只记住"7B"一个总数，就说不清 96% 的参数压在哪里。
↓
2整体结构 的第一笔账落在 Embedding 查表 上：32000×4096 的矩阵占 131M（约 2%），这就要求先把它和后面的矩阵乘法分开——它只按 token ID 取整行，不做乘加。
↓
3向量离开 Embedding 查表 后进入 Block，第一个子层是 Attention，要回答"谁该看谁"——所有关系挤在一条 4096 维通道里学不出多样模式，因此拆成 32 头×128 维各自算注意力（4 个 4096×4096 = 67M）。
↓
432 头 的 Attention 只负责在 token 之间搬运信息，"这些信息意味着什么"没人回答，于是补上 SwiGLU（用门控控制信息通过量的前馈网络） FFN（gate/up/down 三个矩阵，135M，占每层 2/3）；否则模型只是一台搬运机。
↓
5SwiGLU FFN 再强，32 层也叠不起来：少了归一化数值会逐层放大、少了残差梯度衰减到第 1 层就没了，因此每层加 2 个 RMSNorm（各 4096 参数）+ 两条 RMSNorm 与残差捷径，把主干直通下去。
↓
6RMSNorm 与残差捷径 把每层接成主干后，把上面全部串起来跑一次前向：Embedding→32×[Norm→Attn→Res→Norm→FFN→Res]→Final Norm→LM Head，于是得每层约 400M FLOPs、32 层约 12.8G（单 token 前向约 13.5 GFLOPs）、生成 100 token ≈ 1.35T——这就是推理成本的全部来源。

如果拆开一个 Llama 7B 模型，里面到底有几层？每层在干什么？
提示：先想清楚"哪些参数在 32 层里各来一份、哪些只在首尾出现"——把结构拆成 Embedding、Block、输出三部分，再逐块估大小，答案自然浮现。
▾
知识背景
Llama 7B 的结构：1 个 Embedding 层 + 32 个 Transformer Block + 1 个 LM Head。参数量 = 6.74B（四舍五入为"7B"）。每层 Block ≈ 202M（Attention 67M + FFN 135M）。Embedding 仅 131M（约 2%）。同系列的 LLaMA-13B 在多数基准上超过了 GPT-3（175B），参数量不到它的十分之一（Touvron et al., Meta, 2023）。

Llama 2 7B 的架构由三部分组成：Embedding 层 → 32 个 Transformer Block → LM Head。每个 Block 内部又分成 Attention 和 FFN 两个子层，每个子层前后各有一个 RMSNorm。

可以把这一结构类比成一条装配线：首尾各有一个工位，中间几十个工位做完全相同的加工——Transformer 里这些"工位"叫 Block，只是重复了很多次。

🎯 关键认知

7B 参数的 96% 在 32 个 Transformer Block 里。每个 Block 又分配为：Attention 占 33%（67M/202M），FFN 占 67%（135M/202M）。FFN 矩阵是模型"知识存储"的主体——这也是为什么 FFN 比 Attention 大两倍。

从"你好"两个字到一堆 4096 维向量——Embedding 层到底做了什么运算？
提示：Embedding 层本质上就是一个巨大的查表操作——32000 行的矩阵，每行是一个 4096 维的向量。拿到 token ID 后，直接取对应行。
▾
知识背景
Embedding 矩阵 = V × d = 32000 × 4096 = 131M 参数。本质：一个巨大查找表——取 token ID 对应行的 4096 维向量。Weight Tying（权重绑定）：让 Embedding 和 LM Head 共享同一个矩阵，省下一份参数。原论文《Attention Is All You Need》(2017) 第 3.4 节已采用；Inan et al.（2016）与 Press & Wolf（2017）分别系统讨论了它的收益与做法（GPT-2 等沿用）。但 Llama 2 并未使用——它的 LM Head 是一个独立的 131M 输出矩阵。

上一张卡片我们看完了 Llama 的整体结构（Embedding → 32 Blocks → LM Head）。现在聚焦第一站：Embedding 层的数学极其简单——矩阵查表。有一个 32000×4096 的矩阵 W_embed，token ID 为 t 时，输出就是 W_embed 的第 t 行。

这一步就像查一本字典：token ID 是页码，翻到那一页整行搬走，不需要做任何乘加——Embedding 层的运算只有取行这一步。

🎯 Embedding 矩阵与 LM Head 是两个独立矩阵

Llama 2 的 Embedding 矩阵 W_embed（[32000, 4096]）负责把 token ID 映射为向量；最后的输出投影 LM Head 是一块独立的 [4096, 32000] 矩阵 W_out，把最后一层的 [1, 2, 4096] 映射回 [1, 2, 32000] 词表概率。二者并不共享权重（tie_word_embeddings=False）——6.74B 这个总数里已经分别算了这两块各 131M。Weight Tying（共享）是 GPT-2 等模型的做法，可省一份参数，但 Llama 2 没有采用。

一个 Attention Head 里，Q、K、V 到底是怎么从输入一步步算出来的？
提示：先想 Q/K/V 从哪来——输入分别乘三个权重矩阵得到；再想那 4096 维怎么分给 32 个头，每个头算的注意力维度是多少？
▾
知识背景
Attention 层内部包含 4 个权重矩阵：W_Q、W_K、W_V、W_O（各 4096×4096 = 16.8M → 共 67M）。流程：输入 × W_Q/W_K/W_V → 拆 32 头（每头 128 维）→ RoPE 旋转 → QK^T/√128 → Softmax → ×V → 拼接 → ×W_O。每头独立学习一种关系模式。

上一张卡片我们把"你好"变成了两个 4096 维向量。现在它们进入 Attention 层——Transformer 的核心计算单元。输入 [1, 2, 4096]，经过 QKV 投影 → 注意力计算 → O 投影，输出还是 [1, 2, 4096]。

用图书馆借书来类比：Q 是手里的索书号，K 是书脊上的分类标签，V 是书页里的正文——拿 Q 去和每张 K 比对，谁最像就借走谁的 V。

🎯 为什么用 32 个头？

多头注意力的关键是让不同头关注不同的语义关系。研究者发现（Clark et al., 2019），训练后的模型里某些头倾向于关注"主语-谓语"关系，另一些头关注"形容词-名词"修饰，还有些头关注位置相邻性（哪一头对应哪种关系并无固定编号，此处为示意说明）。如果只有一个头（4096 维直接做 Attention），所有关系会混在一起，模型学不出这么多样的注意力模式。32 个头 = 32 种不同的"视角"同时看同一句话。

4
一个 token 走完 32 层 Llama 2 7B，到底要算多少次浮点运算？
提示：先想一件事——每一次权重参与运算，要花几次浮点操作？把这个数乘以参数量，会得到什么？
▾
知识背景
FLOPs（Floating Point Operations，浮点运算次数：衡量计算量的单位，一次浮点乘或一次浮点加各算 1 次）是算力核算的通用货币。经验规则：前向 FLOPs ≈ 2 × 参数量——因为每个权重在一次前向里做一次「乘 + 加」= 2 FLOPs。训练再按 3 倍算（前向 2N + 反向 4N = 6N），就是 Kaplan et al.《Scaling Laws for Neural Language Models》（arXiv:2001.08361, 2020）与 Hoffmann et al.《Training Compute-Optimal Large Language Models》（Chinchilla, arXiv:2203.15556, 2022）反复使用的 C ≈ 6ND 口径。痛点：光知道「7B」这一个数，算不出它的单 token 计算量——而这条 2N 规则把它变成能口算的估算器。

上一张卡片我们逐步跑完了 Attention 的 5 步计算；这一张换个问法——不再问「怎么算」，而是问「一共要算多少次」。要把一个 token 走完 32 层的计算量压成一个数，只需要一条经验规则：一次前向里，每个权重都恰好做一次「乘 + 加」，也就是 2 次浮点运算（FLOP，Floating Point Operation，一次浮点乘或浮点加）。先把三种口径说清（同一颗权重，按数哪些运算区分）：
① 只数乘法（乘一次算 1）：前向 ≈ 1N = 6.7 GFLOPs；
② 只计前向、乘和加都数（每权重 2 FLOPs）：前向 ≈ 2N = 13.5 GFLOPs；
③ 前向 + 反向（反向约是前向的 2 倍）：训练 ≈ 6N = 40.4 GFLOPs。
本课前向采用口径 ②、训练采用口径 ③，两者口径统一（②×3 = ③）。

把这条规则套到参数量上，就得到本课要记住的 2N 规则：前向 FLOPs ≈ 2 × 参数量。它就像一条「流水线计件工资」的口算公式——每个权重是一名工人，每过一次前向固定领 2 次浮点操作，把工人总数（参数量）乘 2 就是这一趟的总工时。

1.为什么是 2N 而不是 N？一个权重不就用一次吗？▾

一次权重参与包含「乘」和「加」两步，各算 1 次浮点操作，所以每个权重固定 2 FLOPs。

操作作用FLOPs
乘w × x1
加累加进输出1
合计每权重每次前向2

套到 Llama 2 7B：6.74e9 × 2 = 1.348e10 ≈ 13.5 GFLOPs/token。反过来，单个 [4096, 4096] 矩阵 16.78M 参数 → 2 × 16.78M ≈ 33.6M FLOPs。


2.训练时为什么是 6N，而不是 2N？▾

反向传播要额外算两类梯度：对权重求梯度 ≈ 2N，向下游层传梯度 ≈ 2N，合计约 4N；加上前向的 2N，就是 6N。

阶段每个参数 FLOPsLlama 2 7B 单 token
前向213.5 GFLOPs
反向427.0 GFLOPs
合计640.4 GFLOPs

再乘训练 token 数 D，就是 C = 6ND：6 × 6.74e9 × 1e12 ≈ 4.04 × 10²² FLOPs。


3.这条 2N 规则算得准吗？忽略了什么？▾

它只统计权重矩阵的乘加，忽略 attention 的 O(L²) 项、激活函数和归一化。短上下文下误差小，上下文越长 attention 项越大。

计算项2N 是否计入何时变大
权重矩阵乘加计入始终是主项
attention 打分与加权（∝ L²）未计入上下文越长越大
激活 / 归一化未计入占比很小

经验上（估算，需人工核实）：L 为几百 token 时两者相差不到 10%；L 到数千时 attention 项开始追上 2N。


4.一次 1000 token 的 prompt，prefill 要花多少算力？和逐 token 生成比呢？▾

prefill 把 1000 个 token 一次性过前向，按 2N 算就是 1000 倍的单 token 算力；decode 每步只算 1 个新 token。

5
FFN 的中间维是 11008——这个怪数字到底是怎么定出来的？
提示：先看标准 FFN 用几个矩阵、中间维取多少；再看 SwiGLU 用几个矩阵。要让两者的参数量相当，中间维该怎么变？
▾
知识背景
FFN（Feed-Forward Network，前馈网络：每个 Block 里负责「记忆」的子层）的中间维惯例取 4d——标准 FFN 用 2 个矩阵，中间维是模型维度 d 的 4 倍（原论文 d_model=512 → 中间维 2048）。SwiGLU（Swish-Gated Linear Unit，用 SiLU 做门控的 GLU 变体，由 Shazeer《GLU Variants Improve Transformer》, arXiv:2002.05202, 2020 提出）改用 3 个矩阵（gate/up/down）。3 个矩阵要凑出与标准 FFN 相同的参数量，中间维就必须缩到 2/3——这正是 11008 的来历。

上一张卡片我们用 2N 规则算出了单 token 的算力，也看到参数量几乎都压在 FFN 里；现在回到「这些参数从哪来」这一侧，把 FFN 那个 11008 拆开看。它不是随手取的整数，而是「参数量守恒」倒推出来的结果。先看两种更省事的做法，恰好都不成立：一是不升维（中间维取 d），两个矩阵只有 2 × 4096² ≈ 33.6M，是 4d 版本 134.2M 的约 1/4；二是省掉一个矩阵（gate/up/down 只留两个），配 11008 只剩 2 × 4096 × 11008 ≈ 90.2M，比守恒点 135.3M 少 45.1M/层。而 FFN 正是每层参数的大头（约 2/3），这两刀都会直接砍在「知识存储」的容量上。

道理就像把一份工作量分给不同人数：标准 FFN 是 2 个人干活（2 个矩阵），SwiGLU 是 3 个人干（3 个矩阵）——想让总工作量不变，每个人（每个矩阵的中间维）就得按比例缩到原来的 2/3。

它 = 4096 × 8/3 再向上对齐到 256 的整数倍，目的只有一个：让 SwiGLU 的 3 个矩阵加起来（3·d·d_ff ≈ 8d²）与标准 FFN 的 2 个矩阵（2·d·4d = 8d²）持平。同一套账换个模型照样套——把 d 换掉重算即可；不同实现会在此基础上调（如 Llama 3 8B 用 14336，比 8/3·d 更大，以换取更强表达力）。

1.标准 FFN 的中间维为什么惯例取 4d？▾

这是原论文沿用的惯例：中间维取模型维度 d 的 4 倍，2 个矩阵配 4d 中间维，每层参数 = 2·d·4d = 8d²。

2.8/3 这个系数是怎么推出来的？▾

设中间维为 m·d，让 SwiGLU（3 矩阵）的参数与标准 FFN（2 矩阵、4d）相等即可解出 m。

结构每层 FFN 参数
标准 FFN（2 矩阵）2·d·4d = 8d²
SwiGLU（3 矩阵）3·d·(m·d) = 3md²

所以中间维 = 8/3·d。d = 4096 时 = 10922.7。这正是 Shazeer 论文里「把中间维缩到 2/3」那句话的来源（原文：reduce the number of hidden units d_ff by a factor of 2/3）。

5.为什么不能只用两个矩阵配 11008？▾

Llama 2 由 Meta 于 2023 年 7 月发布（Touvron et al., 2023）。7B 版本公布的配置是：hidden_size（隐藏层维度，每个 token 向量的长度）=4096、32 层、32 个注意力头、FFN（Feed-Forward Network，每层负责「记忆」的前馈子层）中间维 11008、词表 32000；官方标称参数量 6.74B，四舍五入就叫「7B」。痛点：做显存估算时只知道「7B」这一个总数远远不够——你会算不清这 6.74B 到底压在哪些矩阵上、哪一块动一下总账就跟着动。

3.为什么 FFN 中间维是 11008 而不是 8192？这一项差多少参数？▾

11008 来自 8/3 × 4096 ≈ 10923，再向上取整到 256 的整数倍。把它换成 8192 会明显缩水：

中间维每层 FFN（3 个矩阵）32 层合计
110083 × 4096 × 11008 = 135.27M4.329B
81923 × 4096 × 8192 = 100.66M3.221B
差额34.60M1.107B

每层差 135.27M − 100.66M = 34.60M，32 层差 1.107B——约占整个 6.74B 的 16%。FFN 是参数最重的地方，中间维一动，总账就跟着动。


4.官方的 6.74B 和我一块一块加出来的数对得上吗？差额去哪了？▾

对得上。逐块相加（M = 百万）：

账目计算参数
32 层 Block202.38M × 326,476.01M
Embedding32000 × 4096131.07M
LM Head32000 × 4096131.07M
RMSNorm32 × 2 × 4096 + 40960.27M
总计—6,738.42M ≈ 6.74B

6,476.01M + 131.07M + 131.07M + 0.27M = 6,738.42M = 6.738B，四舍五入 6.74B——与官方数字一致。「7B」不是估的，就是这些矩阵乘出来加总的结果。


5.换个大模型，这套加法变吗？比如 Llama 3 8B。▾

不变，只是每项的数字换掉。Llama 3 8B：d=4096、32 层、FFN=14336、词表 128256，而且用了 kv 头 = 8 的 GQA。

账目计算参数
每层 Attention（GQA）2×4096×4096 + 2×4096×102441.94M
每层 FFN3 × 4096 × 14336176.16M
32 层218.10M × 326,979.32M
Embedding + LM Head2 × 128256 × 40961,050.67M
总计—8,029.99M ≈ 8.03B

6,979.32M + 1,050.67M = 8,029.99M ≈ 8.03B，正是官方公布的 Llama 3 8B 参数量。词表从 32000 涨到 128256 后，首尾两张表从 262M 涨到 1,050.67M——占比从约 3.9% 升到约 13%。
