第 29 课：自主研究全景与自主度分级

前 28 课我们把一个 Agent"造出来、接上工具、记住知识、会规划、能训练、可上线"。这一课翻到新的一页——第五部分，问一个更远的问题：AI 能不能自己做研究？做到哪一步了？哪里还不可信？我们不看发布会上的 demo，而是把它拆成一条可测的流水线：先用公开竞赛的奖牌率给一个硬读数，再把"科研"拆成五条必须成立的工作流条件，然后拿出一把 L1–L5 的自主度尺子定位今天的位置，接着说清哪个领域更可信、它和我们前 9 课学的 Agent 差在哪，最后落到三条可测性判据，教你在几分钟内识破"演示级"产品。

🎯 学完这 6 步你将能够：
① 说出自主研究的五条工作流条件与各自的失败代价
② 用 L1–L5 判断一个系统处在哪一级、瓶颈是什么
③ 用三条可测性判据（held-out / 审计事件数 / 可回滚）识破"演示级"产品

1要判断它能不能做研究，这就要求先拿一个硬读数——公开竞赛 MLE-bench 上的奖牌率，而不是看 demo 有多流畅。先要一个硬读数。
↓
2既然「先要一个硬读数」，可奖牌率只反映终点，所以得把"科研"拆成五步流水线：文献锚定 / 假设与规划 / 实验与工具 / 反馈与验证 / 报告与传播——每一步都要真的烧掉 flops（浮点运算量，用来衡量算力消耗）与机时，断一环整条就废，MLE-bench 的奖牌率也就上不去。先拆成可测的流水线。
↓
3既然「先拆成可测的流水线」，这就要求一把尺子量它能不看人跑多久、跨多少个上下文窗口——于是有了 L1–L5 自主度分级；前沿站在 L4，L5 仍是构想。得有一把自主度的尺子。
↓
4既然「得有一把自主度的尺子」，那么同一级在不同领域含义不同——所以还得看这个领域能不能真的执行、能不能便宜地验证——这就决定 L1–L5 里同一级在两边能走多远，即域条件性（domain-conditioned autonomy ceiling）。还要看领域可不可信。
↓
5既然「还要看领域可不可信」，那么这条"领域上限"决定的正是每个任务能自动化的边界；因此要把研究型任务和我们前 9 课学的普通 Agent 任务放在一起比，看差别落在哪三条：长时程（烧掉远超单轮问答的 token 预算）、延迟反馈、结论要负责（工具与多智能体已在第 20–28 课讲过，此处不重讲）。说清它和一般 Agent 的差别。
↓
6既然「说清它和一般 Agent 的差别」，所以最后落到三条可测性判据——held-out、审计事件数、可回滚，用它在一分钟内判断一个"AI 科研"产品是真本事还是演示。三条可测性判据。

AI 现在到底能不能自己做研究了？
提示：别只看发布会上的 demo，先给它找一个公开、可比的读数——不看它怎么说，看它在别人出的考场上考得怎么样。
▾
知识背景
MLE-bench（OpenAI Preparedness，arXiv:2410.07095，ICLR 2025 Oral）把 75 个 Kaggle 竞赛做成离线考场：Agent 要读题、准备数据、训练模型、调试、提交，最后按人类排行榜的铜 / 银 / 金牌线判分——拿到铜牌，就等于"达到人类选手的奖牌级"。发布时最强配置 o1-preview + AIDE 拿到奖牌的竞赛占比 16.9%，其 pass@8 为 34.1%。

这是第五部分「自主研究」的第一课。前面九课（第 20–28 课）我们在造一个能干活的 Agent；现在问一个更远的问题：它能自己做研究吗？

但"会写论文"这种演示说明不了什么——真正可信的证据，是它在没被特别照顾的公开考场上能拿到什么名次。就像招研究员不看自我介绍，看他有没有在公开竞赛里上过榜。所以先看一个可比的硬读数：MLE-bench 上的奖牌率。

提示：把"科研"当成一条流水线拆开，看看哪一步断了整条就废。

知识背景
综述《AutoResearch AI》（Tie 等，arXiv:2605.23204）把科研自动化拆成五条反复出现的工作流条件：文献锚定、假设生成与规划、实验与工具使用、反馈·验证·评审、报告与知识传播。任一条断了，整条闭环就合不上。

"自主"到底分几级，它现在到哪一级了？
提示：从两个维度想：它能自己决定什么、能不看人跑多久。
▾
知识背景
综述《从 Copilots 到 Colleagues》（Deli Chen，2026）提出 L1–L5 五级自主度分级体系：分级只看两个维度——① 它能对什么内容独立做决定，② 在没人审核时能连续自主运行多久。它对 17 个系统做六维分析后指出：前沿系统普遍处于 L4，L5 仍是目标构想。

上一张卡片把科研拆成五步。接下来要问：这五步它到底能自己走几步、能走多久？这需要一把尺子。

L1–L5（一把把"自主程度"分成五档的尺子，L1 最低、L5 最高）就是这把尺子，它只看两件事：能自己决定什么 + 能不看人跑多久。就像自动驾驶分级：L2 手不能离方向盘，L4 在限定区域可脱手，L5 才全场景无人。

4
同一个自主级别，做 ML 研究和做生物研究，能不能走到同样的深度？差在哪些条件上？
提示：看两件事：实验能不能自动执行、结果能不能很快验证。
▾
知识背景
AutoResearch 综述（Tie 等，arXiv:2605.23204）提出"域条件性"（domain-conditioned autonomy ceiling）：计算与形式科学最容易闭环，实验类学科受物理与安全约束，自动化天花板更低。它的判断依据是四个条件：可执行、反馈快、可复现、伦理约束小。

上一张卡片把自主度分成 L1–L5。但同一个级别在不同领域含义不同——同样是 L4，做 ML 和做生物能走到的深度差很远。

所以要引入"域条件性"（domain-conditioned autonomy ceiling，指一个领域本身允许自动化走到多高）。就像在厨房做菜 vs 在野外做菜：厨房里调料随时可尝、可回锅；野外要先找食材、等天气，做完才发现不对也没法重来。

🧮 第四笔账：领域条件决定天花板
Step 1：四个决定可信度的条件
条件含义
可执行实验能不能在计算机内自动跑
反馈快结果多久能拿到（分钟级还是月级）
可复现换台机器能不能得到同样结果
伦理约束小是否涉及人体、安全等不可逆后果
算术无关的一条拆解：四个条件里任一条差，闭环就会在那一环断掉——"域条件性"本质是这四项的合取。其中"伦理约束小"是一个否决项：一旦不满足（涉及人体、安全等不可逆后果），直接判不可行，因此不参与后面的均值打分——均值只取前三条可量化的条件。

算术：(1.0 + 0.9 + 0.9) ÷ 3 ≈ 0.93，(0.4 + 0.3 + 0.4) ÷ 3 ≈ 0.37；0.93 ÷ 0.37 ≈ 2.5×（示意打分，非论文读数，需人工核实）。均值只对可执行 / 反馈快 / 可复现三项取——第四条"伦理约束小"是否决项（见 Step1），不计入均值。
Step 3：闭环断在哪一环
环节ML 研究生物研究
跑实验计算机内自动需湿实验 / 人体
拿反馈分钟—小时周—月
同样跑 30 天可迭代很多轮可能不到 1 轮
算术：把两者换算到同一单位——生物一轮约 30 天 = 30 × 24 × 60 = 43,200 分钟；若 ML 单轮按小时级（约 60 分钟）计，同样 30 天里 ML 能跑的轮数约为生物的 43,200 ÷ 60 = 720×（示意）。反馈越慢，同一窗口里能迭代的轮数越少，闭环就断在"验证"这一环。

不是工具怎么调，而是三件事：跑得久、反馈慢、结论要有人负责。这就要求重新设计"人在哪里介入"和"账怎么算"。就像一般 Agent 像打车（一段路、很快到），研究型 Agent 像备战一场马拉松（周期长、看长期指标、教练要对结果负责）。

Step 1：本部分特有的三条约束
约束和一般 Agent 的差别
长时程一次任务可能跑几小时到几天，不是单轮问答

结论要负责产出写进论文，必须可追溯、可复现、有人署名
算术无关的一条区分：工具调用解决"能不能做"，这三条约束解决"能不能长时间、可信地做完"——后者是本部分的新问题。

6
怎么判断一个"AI 科研"产品是真本事还是演示？
提示：先问自己——要凑齐哪些证据，才敢相信一个"AI 科研"产品不是演示？答案不止一条，先想三十秒。
▾
知识背景
held-out（留出集：训练与调参阶段都没见过、只在最后验收时用一次的数据）。审材料多少决定能不能查出问题：CMU 一项审计研究（Luo 等，arXiv:2509.08713）用 LLM 当审计器，只看最终论文时二分类准确率约 55%（F1 0.51），加上完整轨迹日志与代码后升到约 82%（F1 0.81）。注意：这是审计器的检测准确率，不是科研系统本身的正确率——它衡量的是"能不能把关"，不等于"科研结果对不对"。

上一张卡片把研究型 Agent 和一般 Agent 分开。最后一个问题：面对一个声称"AI 科研"的产品，怎么在几分钟内判断它是不是演示？

这就要求三条可测性判据：held-out（别用见过的数据验收）、审计事件数（能不能看到每一步执行）、可回滚（出错能不能撤）。就像验收解题能力：不能拿做过的作业题再考一次，要能翻出每一步草稿，答错了还得能擦掉重来。

🧮 第六笔账：三条可测性判据
Step 1：三条判据各问什么
判据问什么不合格的信号
held-out（留出验收集）验收数据它训练 / 检索时见过吗用公开榜单当验收
审计事件数每一步执行有记录吗只能看到最终 PDF
可回滚出错能撤销吗写操作不可逆
算术无关的一条分工：held-out 管"结果是不是真的"，审计事件数管"过程看不看得见"，可回滚管"出事能不能收场"——三者缺一不可。
Step 2：审计材料越多，越能查出问题
审计方式准确率F1
只看最终论文55%0.51
论文 + 轨迹日志 + 代码82%0.81
差82 − 55 = 27 个百分点0.81 − 0.51 = 0.30
算术：82 − 55 = 27（个百分点），0.81 − 0.51 = 0.30（来源：arXiv:2509.08713）。审核材料越全，越能查出问题——"只能看 PDF"本身就是不合格信号。
Step 3：held-out 为什么不能省
验收集结论可信度
被训练 / 检索见过分数虚高
held-out（只在最后用一次）才反映真实能力
75 个竞赛里 20% 被见过（示意）纯 held-out 只剩 75 × 80% = 60 个
算术：75 × (1 − 0.20) = 60（示意见过比例）。用"见过的题"当验收，等于把作业题当期末考；held-out 才有意义——注意 MLE-bench 的污染实验显示混淆题面后分数无显著变化，污染贡献有限（需人工核实）。
🎯 关键认知

识破演示级产品的三条判据：held-out（别用见过的数据验收）、审计事件数（只看 PDF 等于没审）、可回滚（出错要能撤）。而 provenance（出处可追溯：每个结论能点回它的来源与执行记录）正是把这三条落到证据上的机制。这套判据会在第 33 课展开成"验证与评审"。
